# Release strategy
Proposed sequence: `0.1.0` (initial app), `0.2.0` (core workflow), `0.3.0` (quality/security), then `1.0.0` after acceptance checks.
Use Semantic Versioning: MAJOR for incompatible changes, MINOR for backward-compatible functionality, PATCH for compatible fixes.
Release checklist: approved PRs, successful CI, tests passing, dependency/security review, artifact published, deployment approval, smoke test, release notes, rollback plan.
These are planned steps until performed and evidenced in Azure DevOps/GitHub.
